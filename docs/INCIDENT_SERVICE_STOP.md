# تقرير توقف الخدمة بعد الخمول

## النتيجة

التوقف الذي حدث بعد النوم ليس عطلًا عشوائيًا في كود السحب. العملية التي كانت تشغل خادم Node وبوت Discord داخل بيئة التطوير في Manus تعمل ضمن بيئة قابلة للنوم عند عدم النشاط. عند النوم تنتهي عملية التطوير وينقطع اتصال Discord Gateway والعامل. بعد إيقاظ البيئة عادت العملية للعمل، وظهر في سجلها تشغيل الخادم واتصال البوت وتحديث أربعة أوامر.

## الأدلة من السجل

| الملاحظة | معناها |
|---|---|
| `Server running on http://localhost:3000/` | خادم الويب بدأ من جديد بعد إيقاظ البيئة. |
| `[Discord] Connected as سحب#0452` | اتصال Gateway عاد بعد بدء العملية. |
| `[Discord] Guild commands refreshed (4)` | الأوامر الأربعة سُجلت عند الاتصال. |
| `Dev server exited with code -1` في تشغيل سابق | إعادة تشغيل لعملية التطوير، وليس دليلًا على تلف البيانات. |
| استجابة `/api/healthz` بقيمة HTTP 200 | الخادم يعمل حاليًا بعد إيقاظ البيئة. |

## سبب اختلاف اللوحة عن البوت

النسخة المنشورة من لوحة WebDev يمكن أن تبقى متاحة لأنها واجهة HTTP قابلة للتشغيل عند الطلب، بينما لا تبدأ Gateway والعامل في الإنتاج افتراضيًا. هذا القفل مقصود لمنع تشغيل نسختين بتوكن Discord نفسه والتسبب في `40060 Interaction has already been acknowledged`.

## الحل الدائم

يجب نشر المشروع على Railway كخدمة واحدة مستمرة، ثم ضبط `NODE_ENV=production` و`DISCORD_GATEWAY_ENABLED=true` و`JOB_WORKER_ENABLED=true`. يجب ألا تشغل أي نسخة محلية أو Preview أو خدمة ثانية Gateway بالتوكن نفسه. ويُفضّل إبقاء المراقبة في خدمة Cron منفصلة لا تتصل بـ Gateway.

التفاصيل العملية موجودة في [`RAILWAY_DEPLOYMENT.md`](RAILWAY_DEPLOYMENT.md).
