# Manga Drive Discord Bot

منصة عربية لإدارة طلبات سحب فصول المانهوا من المصادر المصرح بها عبر **Suwayomi Server**، ثم تنزيل صفحات الفصل، دمجها في صور PNG رأسية مرتبة، ورفع الناتج إلى Google Drive مع إرسال رابط المجلد إلى العضو الطالب في Discord.

## مكونات المشروع

| المكوّن | المسار | الوظيفة |
|---|---|---|
| لوحة الإدارة | `client/` | إدارة المصادر والأدوار وسياسة مشاركة Drive ومراقبة الطابور والسجل. |
| خادم الويب وواجهة API | `server/_core/` و`server/routers.ts` | المصادقة، tRPC، فحص الصحة، إعدادات التكامل، وخدمة ملفات اللوحة. |
| بوت Discord | `server/services/discordBot.ts` | أوامر `/فصل` و`/دمج` و`/مساعدة` ورسائل Components V2 العامة. |
| عامل الطابور | `server/services/jobWorker.ts` | جلب الصفحات من Suwayomi، دمجها، رفع PNG إلى Drive، وإرسال النتيجة. |
| الدمج | `server/services/imageMerging.ts` | عرض موحد بالتحجير، وأقل عدد من الصور بارتفاعات متساوية حول عتبة ~14000 بكسل (سقف مرن 15000)، دون قص أو ضغط خساري. |
| تكامل Suwayomi | `server/services/suwayomi.ts` | استخدام GraphQL والإضافات المثبتة فعليًا فقط. |
| تكامل Google Drive | `server/services/googleDrive.ts` | إنشاء المجلدات تلقائيًا وضبط المشاركة ورفع الصور الناتجة فقط. |

## سبب توقف الخدمة بعد النوم

البيئة التي يعمل فيها المشروع داخل Manus ليست خادمًا دائمًا. عند عدم النشاط قد تدخل بيئة التطوير في وضع السكون، فتتوقف عملية Node وWebSocket الخاص بـ Discord؛ وعند إيقاظ البيئة يبدأ الخادم من جديد. هذا ليس عطلًا في خوارزمية السحب ولا في Suwayomi.

كذلك، النسخة المنشورة من لوحة WebDev تشغّل واجهة الويب، لكن تشغيل Discord Gateway والعامل في عملية الويب الإنتاجية معطّل افتراضيًا لتجنب اتصالين متنافسين وظهور الخطأ `40060`. لذلك يمكن أن تبقى اللوحة قابلة للفتح بينما يكون البوت غير متصل. الحل التشغيلي الدائم هو نشر المشروع على Railway وتشغيل نسخة واحدة فقط مع `DISCORD_GATEWAY_ENABLED=true` و`JOB_WORKER_ENABLED=true`.

## التشغيل المحلي

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm test -- --run
pnpm build
pnpm dev
```

يستمع الخادم إلى `PORT` الذي توفره البيئة. في التطوير يفعّل الكود Gateway والعامل افتراضيًا، أما في الإنتاج فلا يتم تفعيلهما إلا إذا ضُبط المتغيران صراحة.

## أوامر Discord

| الأمر | الوظيفة |
|---|---|
| `/فصل الرابط:<URL>` | سحب فصل مصرح به ودمجه ورفعه إلى Drive برابط جاهز. |
| `/دمج` | دمج صور جاهزة بدون سحب: أرفق ملف **ZIP/CBZ** أو ضع رابط مجلد Google Drive يحتوي الصور. |
| `/مواقع` | عرض كل المواقع المتاحة مرتبة في أقسام لغوية (العربية، الإنجليزية، …) — أي موقع يُضاف يظهر تلقائيًا. |
| `/بحث الاسم:<اسم> الفصل:<رقم اختياري>` | البحث عن أي عمل في كل المواقع مع ترقيم صفحات النتائج مهما كثرت، واختيار العمل يفتح صفحته: الغلاف والملخص والمؤلف والحالة والتصنيفات والعدد الكلي للفصول، وقائمة فصول صفحة صفحة — اختيار الفصل يسحبه فورًا كأمر /فصل. |
| `/نقل من:<رابط أو عدة روابط> إلى:<رابط مجلد>` | نقل مجلدات الفصول إلى مجلد الوجهة دفعة واحدة: رابط واحد يعني نقل كل ما بداخله، وعدة روابط (مفصولة بمسافات أو أسطر) تعني نقل هذه المجلدات نفسها من أي مكان. عند فشل الوصول تُظهر البطاقة حساب Drive الذي يستخدمه البوت لتشاركه معه المجلد بصلاحية محرر. |
| `/مساعدة` | عرض طريقة الاستخدام وشرح كل أمر. |

جميع الأوامر عربية فقط. عند تنفيذ `/فصل` أو `/دمج` بدون مدخلات تظهر لوحة طلب مدخلات وتُقبل الإجابة كرسالة عادية خلال دقيقتين.

## ملاحظات الدمج

بعد جلب الصفحات، يُوحد عرض كل الصور بالتحجير إلى العرض الأكثر تكرارًا مع الحفاظ على النسبة (لا حشو أبيض ولا تشويه). ثم تُقسم صفحات الفصل إلى **أقل عدد ممكن** من الصور المتصلة بشرط ألا يتجاوز ارتفاع أي صورة السقف المرن **15000 بكسل** حول عتبة ~14000، وبين التوزيعات ذات العدد الأدنى يُختار التوزيع الأكثر تساويًا في الارتفاع فتخرج صور الفصل متقاربة الطول. تُدمج الصفحات الصغيرة اثنين أو ثلاثة أو أكثر حتى تبلغ العتبة. لا يقص الصفحة ولا يقسمها ولا يعيد ترتيبها؛ والصفحة الأطول من السقف تبقى كاملة في صورة مستقلة. تُرفع ملفات PNG المدمجة فقط، ولا تُرفع الصفحات الأصلية إلى مجلد Drive النهائي.

## مجلدات Drive والصلاحيات

البنية: `Manga Drive Discord Bot` ← `اسم العمل [نطاق الموقع]` ← مجلد الفصل ← الصور المدمجة. افتراضيًا يُنشأ مجلد الفصل بصلاحية **محرر لأي شخص يملك الرابط** ليتسنى تنظيم المجلدات ونقلها (يمكن تغييرها من صفحة الإعدادات: قارئ / خاص / نطاق Workspace). أمر `/نقل` ينقل المجلدات بتغيير موضعها فقط دون تعديل معرّفاتها، فتبقى كل الروابط القديمة تعمل.

## النشر على Railway

التعليمات التفصيلية موجودة في [`docs/RAILWAY_DEPLOYMENT.md`](docs/RAILWAY_DEPLOYMENT.md). ملف `railway.toml` يحدد البناء عبر `pnpm build` والتشغيل عبر `pnpm start` وفحص الصحة عبر `/api/healthz`.

قبل الاعتماد اليومي، يجب أن تكون قاعدة MongoDB متصلة، ومتغيرات Discord وGoogle Drive وSuwayomi محفوظة في Railway Variables، وأن تكون هناك **نسخة واحدة فقط** من الخدمة مفعّلًا فيها Gateway والعامل. لا تضع أي قيمة سرية في Git أو ملف داخل الأرشيف.

## الاختبارات

```bash
pnpm test -- --run
pnpm check
pnpm build
```

الاختبارات الحالية تغطي التحقق من الروابط، منع التكرار، انتقالات حالات الطابور، تكاملات الاتصال، رسائل Discord، وخوارزمية الدمج والعرض الموحد.

## الأمان

يقبل النظام النطاقات والمصادر التي يسجلها المالك فقط، ويرفض روابط تسجيل الدخول وCAPTCHA والمصادر غير المثبتة في Suwayomi. لا تستخدم هذه الحزمة لتجاوز حماية مصدر أو الوصول إلى محتوى دون تصريح. احفظ الأسرار في Railway Variables فقط، وفعّل مصادقة قاعدة البيانات وTLS عند توفرهما.
